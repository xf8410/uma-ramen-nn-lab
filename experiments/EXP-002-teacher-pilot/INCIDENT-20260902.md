# EXP-002 跑批事故记录（2026-09-02）

## 现象
run 33580762360：8 个 collect 分片全部 success，assemble 校验挂——
`shard 1 区间错: [1500,4500)`（期望 [1500,3000)）

## 根因（run.sh 数据语义 bug，非矩阵架构问题）
`--count` 在 ramen_teacher_collect 里是**累计目标**：区间 = `[--start, --start + --count)`。
run.sh 里写成了 `--count $((START + CHUNK))`（忘了减 START）：
- shard0: START=0 → count=1500 → [0,1500) ✅ 碰巧对
- shard1: START=1500 → count=3000 → [1500,4500) ❌ 多采 1500
- shard7: START=10500 → count=12000 → [10500,22500) ❌ 越界采样到未定义区间

## 事故分级
- shard1-7 采了超过配额的数据（shard7 采了 12000 条而非 1500，index 10500-22499）
- **脏数据**：index ≥12000 的样本是采样器未定义区间，不能进训练集
- 好消息：数据分片是按 [start, next_index) 记录的，只要**截断保留 index<12000 的部分**，[0,12000) 区间内的样本仍然有效——因为采样按 index 确定性，前面的区间不受后面多采影响

## 修复
- run.sh：`--count $((START + CHUNK))` → `--count $((START + 1))`（冒烟）与 `--count $((START + CHUNK))` → `--count CHUNK`——**count 是长度不是终点**。
  正确语义：`--count 1500 --start 1500` = 区间 [1500,3000)
- assemble 校验逻辑不动（区间无缝检查是对的，它拦住了脏数据）

## 教训
1. `--count` 累计语义——文档写了但写脚本时按"终点"理解了
2. assemble 的区间断言是防脏数据的好闸门，保留
